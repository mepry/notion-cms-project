## 2. 개요

### 2.1 목적

Notion을 CMS(Content Management System)로 활용한 개인 포트폴리오 사이트를 만든다. 개발하면서 Notion에 정리한 내용을 그대로 웹사이트에 글로 보여준다.

### 2.2 CMS로 Notion을 선택한 이유

- 이미 개발 내용을 Notion에 정리하고 있어 **작성 도구를 바꿀 필요가 없다.**
- Notion API로 데이터베이스와 페이지 본문을 가져올 수 있어 **별도 관리자 페이지나 DB 없이** 글을 발행·수정할 수 있다.
- Notion의 속성(카테고리, 태그, 날짜, 상태)을 그대로 필터와 정렬 조건으로 쓸 수 있다.

## 3. 목표 / 비목표

### 3.1 목표

- Notion에서 글을 쓰고 `Status`를 `발행됨`으로 바꾸면 사이트에 자동으로 반영된다.
- 방문자가 날짜·카테고리 필터와 검색으로 원하는 글을 빠르게 찾을 수 있다.
- 홈에서 올해 작성 기록을 GitHub 잔디처럼 한눈에 보여준다.
- 모바일·태블릿·데스크톱에서 모두 읽기 편하다.

### 3.2 비목표 (MVP 제외)

- 회원가입/로그인, 댓글
- 사이트 안에서 글 작성·편집 (편집은 Notion에서만)
- 다국어 지원
- 조회수·좋아요 등 통계

## 4. 대상 사용자

| 사용자        | 니즈                                                      |
| ------------- | --------------------------------------------------------- |

| 개발자 방문자 | 특정 기술(카테고리·태그) 관련 글을 검색해서 읽음          |

## 6. Notion 데이터베이스 구조

| 속성명    | 타입         | 필수 | 설명                                           |
| --------- | ------------ | ---- | ---------------------------------------------- |
| Title     | title        | O    | 글 제목                                        |
| Category  | select       | O    | 카테고리 (예: Frontend, Backend, DevOps, 회고) |
| Tags      | multi_select | -    | 태그 (예: Next.js, TypeScript, Docker)         |
| Published | date         | O    | 발행일. 정렬과 잔디 그래프의 기준              |
| Status    | select       | O    | `초안` / `발행됨`                              |
| Content   | page content | O    | 페이지 본문 (Notion 블록)                      |

**노출 규칙**

- `Status = 발행됨` 이고 `Published` 값이 있는 글만 사이트에 노출한다.
- 목록은 `Published` 내림차순으로 정렬한다.

## 7. 기능 요구사항

| ID  | 기능                  | 우선순위 | 범위 |
| --- | --------------------- | -------- | ---- |
| F1  | Notion 글 가져오기    | P0       | MVP  |
| F2  | 날짜·카테고리 필터링  | P1       | MVP  |
| F3  | 검색                  | P1       | MVP  |
| F4  | 작성 기록 잔디 그래프 | P1       | MVP  |

### F1. Notion에서 글 가져오기

- 데이터베이스를 조회할 때 `Status = 발행됨` 필터와 `Published` 내림차순 정렬을 적용한다.
- 100건이 넘으면 `next_cursor`로 이어서 모두 가져온다.
- 페이지 본문 블록을 가져와 HTML로 렌더링한다. 지원 블록:
  - 제목(heading 1~3), 문단, 글머리/번호 목록, 할 일 목록
  - 코드(언어별 구문 강조), 인용, 콜아웃, 구분선
  - 이미지, 북마크/링크, 토글
- 하위 블록(`has_children`)은 재귀로 가져온다.
- 지원하지 않는 블록은 화면을 깨뜨리지 않고 건너뛴다.

### F2. 날짜 및 카테고리 필터링

- 연도 / 월 단위 필터를 제공한다.
- 카테고리 필터를 제공한다 (카테고리 페이지와 목록 상단 칩).
- 필터 상태는 URL 쿼리 파라미터(`?year=2026&month=10&category=Frontend`)로 유지해 공유·새로고침해도 그대로 보인다.

### F3. 검색

- MVP: 제목과 태그를 대상으로 대소문자 구분 없이 검색한다.
- 검색어는 `?q=` 쿼리 파라미터로 유지한다.
- 결과가 없으면 빈 상태 안내 문구를 보여준다.
- 후속: 본문 전문 검색.

### F4. 작성 기록 잔디 그래프

- 올해 1월 1일 ~ 12월 31일을 53주 × 7일 그리드로 표시한다 (GitHub contribution 그래프 형태).
- 셀 색은 해당 날짜 발행 글 수에 따라 0 / 1 / 2 / 3+ 단계로 진하게 표시한다.
- 셀에 마우스를 올리면(모바일은 탭) `2026-10-20 · 글 2개` 형식의 툴팁을 보여준다.
- 셀을 클릭하면 그 날짜의 글 목록으로 이동한다.
- 모바일에서는 가로 스크롤로 전체 그리드를 볼 수 있다.

## 9. 데이터 흐름 / 아키텍처

```
Notion DB ──(Notion API)──▶ Next.js Server Component ──▶ HTML (ISR 캐시) ──▶ 브라우저
```

- Notion 호출은 **서버에서만** 한다 (Server Component / 서버 유틸). API 키는 클라이언트에 노출하지 않는다.
- ISR(`revalidate`)로 페이지를 캐시해 Notion API 호출을 줄인다. 기본 재검증 주기는 60초~1시간 사이에서 정한다.
- Notion API 요청 제한(평균 초당 3회)을 고려해 목록은 한 번에 가져와 캐시하고, 필터·검색은 캐시된 목록에서 처리한다.
- Notion 이미지 파일 URL은 약 1시간 뒤 만료되므로 ISR 주기를 그보다 짧게 두거나 이미지 프록시를 둔다.
- 오류(키 누락, API 실패)는 로깅 라이브러리로 기록하고, 사용자에게는 오류 페이지를 보여준다.

**환경 변수**

| 변수                 | 설명                      |
| -------------------- | ------------------------- |
| `NOTION_TOKEN`       | Notion Integration 시크릿 |
| `NOTION_DATABASE_ID` | 글 데이터베이스 ID        |

## 14. 리스크 및 열린 질문

| 항목            | 내용                                                                                    |
| --------------- | --------------------------------------------------------------------------------------- |
| Next.js 버전    | 요구사항은 Next.js 15, 기존 Starter Kit은 Next.js 16. 어느 버전으로 갈지 결정 필요      |
| 글 URL(slug)    | Notion 페이지 ID를 쓸지, `Slug` 속성(rich_text)을 추가해 읽기 쉬운 URL을 쓸지 결정 필요 |
| 이미지 URL 만료 | ISR 주기를 1시간 미만으로 둘지, 이미지를 프록시·외부 저장소로 옮길지 결정 필요          |
| Notion API 변경 | API 버전·SDK 버전에 따라 DB 조회 방식이 달라질 수 있으므로 구현 시 최신 문서 확인 필요  |
| 요청 제한       | 글이 많아지면 빌드·재검증 시 요청 제한에 걸릴 수 있음 → 캐시 전략으로 대응              |
